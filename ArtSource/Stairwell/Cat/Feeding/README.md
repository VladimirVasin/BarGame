# Stairwell cat-feeding source

This directory owns the approved source sheet for the cat side of the
stairwell feeding interaction. No source or placeholder atlas is generated by
the packer.

## Expected source

The default input is exactly:

`ArtSource/Stairwell/Cat/Feeding/StairwellCatFeedingSource-alpha.png`

It must be an RGB or RGBA PNG containing a `4 x 4` pose grid. A square source
such as `1024 x 1024` is preferred; near-square cells within 10 percent are
accepted and the sheet must be at least `512 x 512`. Generated dimensions do
not need to divide by four: integer half-up boundaries deterministically split
the current `1254 x 1254` approved sheet into cells that differ by at most one
pixel. The raw magenta-backed sibling
`StairwellCatFeedingSource.png` is retained as provenance and can also be
validated explicitly with `--source`. Each computed cell is inset by three
source pixels before cleanup so faint contact-sheet separators cannot enter
the runtime atlas.

The background may be transparent or the locked magenta chroma family. The
builder treats a pixel as chroma background when red and blue are at least
`200`, green is at most `100`, both red and blue exceed green by at least
`100`, and the red/blue difference is no more than `64`. Do not use that color
family in the cat, bowl, can, food or other foreground pixels. Alpha below
`128` is also transparent. The runtime result always has binary alpha and
transparent-black background pixels.

Each cell must contain visible art plus some transparent or keyed background.
Keep the cat's ground contact and apparent scale aligned across all 16 cells.
The builder finds eight-connected foreground components and removes only tiny
artifacts below `max(4 pixels, 0.01 percent of the source-cell area)`. It keeps
every component at or above that threshold, including a disconnected can,
bowl, food or intentional reaction marks. It derives one sequence-wide scale
from the combined retained bounds, grounds those bounds with a four-pixel
runtime margin and uses the largest component's mid-body pixels as the cat's
horizontal anchor.

## Source ordering

Source frames use conventional top-left row-major order:

```text
top     00 01 02 03
        04 05 06 07
        08 09 10 11
bottom  12 13 14 15
```

The authored poses should progress from noticing/lowering toward the food,
through eating, then settling back to the seated idle. Runtime timing, repeats
and holds are defined in code; the sheet contains 16 unique logical poses.

## Runtime packing contract

The output is:

`Assets/Resources/Stairwell/Cat/StairwellCatFeedingAtlas.png`

It is a `512 x 128` RGBA PNG containing `8 x 2` point-sampled `64 x 64`
cells. Cat atlases use the existing cat library's top-first convention, so
logical frame `0` is in the upper-left PNG cell:

```text
visible PNG top     00 01 02 03 04 05 06 07
visible PNG bottom  08 09 10 11 12 13 14 15
```

The feeding loader slices rows from the visible PNG top, exactly like the
existing idle cat atlas. This convention is intentionally different from the
bottom-origin player interaction atlas.

## Validate and build

From the repository root, validate without writing:

```powershell
python tools/build-stairwell-cat-feeding-atlas.py --validate-only
```

Build the runtime atlas:

```powershell
python tools/build-stairwell-cat-feeding-atlas.py
```

Custom paths are available for isolated tooling checks:

```powershell
python tools/build-stairwell-cat-feeding-atlas.py `
  --source C:\path\to\StairwellCatFeedingSource-alpha.png `
  --output C:\path\to\StairwellCatFeedingAtlas.png
```

The builder reads the source without changing it, validates all 16 cells,
packs in memory, verifies exact cell order and binary alpha, and writes the
chosen output through an atomic PNG round trip. `--validate-only` never writes
or creates the output.
